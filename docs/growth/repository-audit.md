# Growth Repository Audit

Audit date: 2026-08-01
Production baseline commit: `ef1324e93c9fa6de54bd059e159d6b509b1af849`
Target site: `https://jipcalc.co.kr`

## Technical Structure

- Framework: Next.js `16.2.6`, React `19.2.6`, TypeScript `5.9.3`.
- Routing: App Router under `src/app`.
- Rendering: static/server-rendered route shells and metadata through App Router pages; individual calculator forms are client components.
- Styling: Tailwind CSS `3.4.19`, global CSS in `src/app/globals.css`.
- Form stack: `react-hook-form`, `zod`, `@hookform/resolvers`.
- Test stack: Vitest with jsdom; Playwright is present as a dev dependency for scripted checks.
- Production build command: `npm run build`, which runs `next build` and `scripts/seo-audit.mjs --source`.
- Render build command: `npm ci && npm run build`.
- Render start command: `npm run start`.

## SEO And Routing

- Canonical metadata is generated by `src/lib/seo.ts` via `buildCalculatorMetadata` and `buildPageMetadata`.
- Calculator metadata comes from `src/config/calculators.ts`.
- Page metadata is exported per route file.
- HTML language is `ko` in `src/app/layout.tsx`.
- Naver site verification is preserved in `src/app/layout.tsx` from `siteConfig.naverSiteVerification`.
- Robots are generated by `src/app/robots.ts`; current rules allow `/`, `/calculators`, and `/guides`, and disallow `/_next/` and `/api/`.
- Sitemap is generated by `src/app/sitemap.ts`; it includes static paths, calculators, and guides, and filters query strings, fragments, and the legacy severance-pay route.
- RSS is generated by `src/app/rss.xml/route.ts`.
- JSON-LD is generated by `src/lib/json-ld.tsx`; calculator pages include WebPage, FAQ, Breadcrumb, and Calculator JSON-LD through `CalculatorPage`.

## Calculator Architecture

- Calculator route pages are thin server components that load calculator config and render `CalculatorPage`.
- `CalculatorPage` renders shared SEO content, FAQ, breadcrumbs, JSON-LD, related links, and the client calculator.
- Client calculator components live in `src/components/calculators`.
- Shared form/result UI lives in `src/components/calculator`.
- Calculation services live in `src/lib/calculators`.
- Official policy/rate data lives in `src/config/*-rates.ts` and `src/config/*-rules.ts`.

## Analytics

- No existing analytics abstraction was found.
- No `gtag`, `dataLayer`, Plausible, or first-party analytics client was found.
- Growth analytics must therefore add a small first-party browser abstraction that is safe when no provider is configured.

## AdFit

- Current AdFit implementation lives in `src/components/adfit/AdFitBanner.tsx` and `src/components/adfit/AdFitPageAds.tsx`.
- Current implementation loads `https://t1.kakaocdn.net/kas/static/ba.min.js`.
- Current units are hardcoded in components.
- Current calculator pages render mobile ads above the calculator hero and desktop top ads after the calculator workspace.
- Growth implementation must preserve existing unit keys as fallbacks but move calculation-page ads behind placement/env/feature flag controls and after results.

## State And Storage

- `src/lib/query-state.ts` currently writes only non-sensitive values to query string and strips sensitive key names.
- Several calculators restore from query string for compatible non-sensitive inputs.
- New share/result state should use URL fragment, keep canonical unchanged, and never enter sitemap.
- Recent calculations should use localStorage only, max 5 entries, 30-day retention, and must degrade silently when storage is unavailable.

## Device Handling

- Current responsive behavior is CSS/Tailwind plus client `matchMedia` hooks in AdFit components.
- Growth AdFit must insert only the matching device slot into the DOM.
- Mobile horizontal overflow prevention is mostly handled by `min-w-0`, `overflow-x-auto` around tables, and global `box-sizing`.

## Protected Baseline

The following should remain unchanged unless a specific defect is found:

- Existing URL paths and slugs.
- Canonical generation policy.
- Robots and index/follow policy.
- HTTPS and www redirect policy.
- Naver verification tag.
- Existing calculation formulas and rate/rule data.
- Existing official basis dates and date metadata unless a real content change requires updating a specific page.
- Existing guide metadata for protected high-performance guide pages.
- Existing AdFit unit keys, retained as fallback keys.
